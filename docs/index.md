# Upwind Provider

The Upwind provider manages Upwind platform configuration declaratively: access
scopes, threat policies, custom detection rules, malware indicators, and
read-only access to threat stories and configuration findings.

## Authentication

The provider authenticates with the OAuth2 client-credentials grant. Create a
service account in the Upwind console to get a client ID and secret, and note
the region your organization is hosted in.

Every setting can be supplied either in the `provider` block or via an
environment variable. **A value set in HCL takes precedence over the environment
variable.**

| Setting         | HCL attribute   | Environment variable   | Notes                                |
| --------------- | --------------- | ---------------------- | ------------------------------------ |
| Region          | `region`        | `UPWIND_REGION`        | One of `us`, `eu`, `me`.             |
| Organization ID | `org_id`        | `UPWIND_ORG_ID`        | e.g. `org_...`.                      |
| OAuth client ID | `client_id`     | `UPWIND_CLIENT_ID`     | Client-credentials grant.            |
| OAuth secret    | `client_secret` | `UPWIND_CLIENT_SECRET` | Sensitive - prefer the env variable. |

The recommended pattern keeps the secret out of your configuration files and out
of your shell history (note the leading space, which most shells exclude from
history):

```bash
export UPWIND_REGION=us
export UPWIND_ORG_ID=org_xxxxxxxxxxxx
 export UPWIND_CLIENT_ID=xxxxxxxx
 export UPWIND_CLIENT_SECRET=xxxxxxxx
```

## Example Usage

```terraform
terraform {
  required_providers {
    upwind = {
      source  = "upwindsecurity/upwind"
      version = "~> 0.1"
    }
  }
}

# Credentials are read from the environment, which is the recommended setup:
#   UPWIND_REGION         us | eu | me
#   UPWIND_ORG_ID         org_...
#   UPWIND_CLIENT_ID
#   UPWIND_CLIENT_SECRET
provider "upwind" {}

# Or set them explicitly. Keep the secret in a variable, never a literal.
provider "upwind" {
  alias         = "explicit"
  region        = "us"
  org_id        = var.upwind_org_id
  client_id     = var.upwind_client_id
  client_secret = var.upwind_client_secret
}
```

## Multiple organizations or regions

Provider configuration is per-organization, so managing more than one means one
aliased provider block per organization and a `provider` argument on each
resource.

## Troubleshooting

Every API call the provider makes is logged. Set `TF_LOG=DEBUG` (or
`TF_LOG_PROVIDER=DEBUG` for provider lines only) and re-run the failing command:

```bash
TF_LOG=DEBUG terraform apply 2>&1 | tee tf.log
grep "Upwind API" tf.log
```

Each request logs the HTTP method and URL, the response status, its size, and how
long it took, alongside the Terraform operation it belongs to (`tf_rpc`) and the
resource or data source that triggered it. Credentials and request/response
bodies are never logged. The body of a *failed* call is not in the log but is in
the error Terraform prints, so include both when opening a support ticket - with
the `upwind_request_id` from the log line if one is present.

## Schema

### Optional

- `client_id` (String) OAuth2 client ID for the client-credentials grant. May also be set via `UPWIND_CLIENT_ID`.
- `client_secret` (String, Sensitive) OAuth2 client secret. May also be set via `UPWIND_CLIENT_SECRET`.
- `org_id` (String) Upwind organization ID (e.g. `org_...`). May also be set via `UPWIND_ORG_ID`.
- `region` (String) Upwind region: `ap`, `eu`, `me`, `us`. Selects the API endpoint and OAuth audience. May also be set via the `UPWIND_REGION` environment variable.
